# Fix M17 + L15: sub-agent orchestration supervision & lifecycle

## Context

All 16 HIGH findings and the prioritized medium tiers of `docs/reports/code-review-2026-06-10.md` are closed. The remaining open findings are M9, M10, M13–M18 and most LOWs. The cluster that makes the most sense next is **M17 + L15** — the two findings the review explicitly flags as compounding the already-fixed H10 (spawn-cap lockout), in the same code paths:

- **M17:** Sub-agent orchestration runs in a bare unsupervised `spawn` (`lib/jido_claw/tools/spawn_agent.ex:88`, `send_to_agent.ex:71`). The tracker monitors the *agent server* pid, not the orchestrator — so if the orchestrator dies while the agent stays alive, `mark_complete` never fires, the entry strands `:running` forever, consumes the spawn cap (default 8), and the H10 sweep (terminal-only) never collects it. `spawn_agent`'s body has **no try/catch** (`send_to_agent` got one during H10 — the asymmetry to close).
- **L15:** Spawned/handed-off agents are effectively `restart: :permanent` (hardcoded in the dep: `deps/jido/lib/jido/agent_server.ex:300-310`) — a crashed finished agent is resurrected by `JidoClaw.Jido.AgentSupervisor` as a new-pid orphan nothing tracks or stops. **Additionally (review finding P1):** `agent_runner.ex:77`'s cleanup `Process.exit(pid, :normal)` is a silent no-op — an exit signal with reason `:normal` sent to another non-trapping process is discarded — so skill-step agents (which are *not* AgentTracker-registered) leak alive today, invisibly.

**Deliberate scope decision for L15:** take the `restart: :temporary` option, **not** "stop after the terminal transcript row". Stopping immediately would break the re-engagement feature deliberately built during H10 (`mark_running` + 30-min TTL sweep lets `send_to_agent` follow up with a finished agent). The TTL sweep remains the stopper for spawned agents; `:temporary` removes the resurrection orphans; AgentRunner gets a *real* stop.

Completion gate: `mix precommit` must pass. No commits — leave everything unstaged. Greenfield: no compat shims.

## Implementation steps (dependency order)

### 1. `JidoClaw.Jido.start_subagent/2` (L15 core)

**File:** `lib/jido_claw/jido.ex` (currently a 12-line `use Jido, otp_app: :jido_claw` shim)

Add a public function after `use Jido`. The dep's `Jido.AgentServer.child_spec/1` hardcodes `restart: :permanent` and ignores `opts[:restart]`, so mirror `Jido.start_agent/3` (deps/jido/lib/jido.ex:442-444 — it is only a child-spec build + `DynamicSupervisor.start_child`) and override restart via `Supervisor.child_spec/2`:

```elixir
@spec start_subagent(module() | struct(), keyword()) :: DynamicSupervisor.on_start_child()
def start_subagent(agent, opts \\ []) do
  child_spec =
    Supervisor.child_spec(
      {Jido.AgentServer, Keyword.merge(opts, agent: agent, jido: __MODULE__)},
      restart: :temporary
    )

  DynamicSupervisor.start_child(agent_supervisor_name(), child_spec)
end
```

- `agent_supervisor_name/0` is generated by `use Jido` → `JidoClaw.Jido.AgentSupervisor`.
- Doc comment must say: mirrors `Jido.start_agent/3`, keep in sync with the dep; main/session agents (`lib/jido_claw.ex:165`, `cli/repl.ex:67`) stay on `start_agent` (`:permanent`).
- Return type matches `start_agent/2`, so existing `{:ok, pid}`/`{:error, _}` matches at call sites are unchanged (dialyzer-safe). `{:error, {:already_started, pid}}` shapes the router handles still come from the same `start_child` call.

### 2. AgentTracker orchestrator-monitor backstop (M17 core)

**File:** `lib/jido_claw/agent_tracker.ex`

- **State:** add `orchestrators: %{ref => id}` (parallel to `monitors`, which stays agent-server-only). Update both construction sites: `init/1` (line 198) and `handle_cast(:reset, ...)` (line 370). Helper `find_orchestrator_ref(state, id)` (Enum.find_value reverse lookup — at most one ref per live sub-agent) and `demonitor_orchestrator(state, id)` (`Process.demonitor(ref, [:flush])` + map delete; `[:flush]` purges any already-queued `:DOWN`, which is what makes stale-orchestrator handling safe).
- **New API** `attach_orchestrator(id, pid)` — a **GenServer.call** (blocks the task until the monitor is armed). Handler: if entry exists → `demonitor_orchestrator` then `Process.monitor(pid)` and store ref; if entry missing → `:ok` no-op. Monitoring a dead pid yields an immediate `:DOWN :noproc`, so attach-after-task-death still forces terminal.
- **`:DOWN` handler** (line 375-384): check `state.orchestrators` first; on hit, pop the ref and route through the existing `complete_entry(state, id, :error, "orchestrator died: #{inspect(reason)}")` — the from-`:running`-only guard makes it a no-op for the happy path. Otherwise fall through to the existing agent-server branch unchanged. Ordering guarantee (verified): the task's `mark_complete` cast and its `:DOWN` come from the same sender to the same receiver, so the cast always lands first — a normal exit never writes "orchestrator died".
- **`reactivate_entry/3`** (lines 411-419): both clauses additionally pipe through `demonitor_orchestrator(state, id)`, so a dying *previous* orchestrator can never error a freshly re-engaged entry.
- **`evict_entries/2`** (lines 475-490): demonitor+drop orchestrator refs for evicted ids, symmetric with the existing `monitors` split. Keep the `(state, [])` early-return clause.
- **Moduledoc** "Lifecycle & retention": add the orchestrator-monitor invariant and document the two accepted residuals (below).

### 5. Remaining L15 call sites

- **`lib/jido_claw/skills/steps/agent_runner.ex`:**
  - Line 55: `JidoClaw.Jido.start_agent(...)` → `JidoClaw.Jido.start_subagent(...)`.
  - Line 77 (**P1 fix**): `if Process.alive?(pid), do: Process.exit(pid, :normal)` → `if Process.alive?(pid), do: JidoClaw.Jido.stop_agent(pid)`. `Process.exit(pid, :normal)` to another process is discarded (verified) — the cleanup has never stopped the worker. `stop_agent/1` (generated by `use Jido`) goes through `DynamicSupervisor.terminate_child`, which genuinely terminates; `{:error, :not_found}` on a dead pid is harmless.
- **`lib/jido_claw/agent/handoff/router.ex:434`** (`jido_start_agent/2`): `runtime.start_agent(module, opts)` → `runtime.start_subagent(module, opts)`. Handoff workers are lazily recreated by `ensure_worker_pid` on whereis-nil, so `:temporary` is safe (no tracker/M17 interaction — they aren't tracked).
- **Handoff prompt re-injection (consequence of `:temporary` recreation, latent today under `:permanent` restarts too):** `maybe_inject_prompt`'s skip clause (`router.ex:437`) keys on a per-session boolean `prompt_injected?` in the in-memory `HandoffRegistry` (`lib/jido_claw/agent/handoff/registry.ex`), so a recreated worker (fresh pid, empty state) is skipped because a *previous* incarnation was injected. Fix by **pid-keying the marker** (registry is in-memory, pids are node-local-safe):
  - Registry: replace `prompt_injected?: boolean()` with `prompt_injected_pid: pid() | nil` — typespecs (lines 19, 46), moduledoc notes (26, 80), `put_owner` opt default (138), and `mark_prompt_injected/2` → `mark_prompt_injected/3` taking the injected worker pid (104-108, 154-158). Greenfield — no compat shim.
  - Router: skip clause becomes a pinned same-pid match — `defp maybe_inject_prompt(pid, %{prompt_injected_pid: pid}, ...), do: :ok` — and the success path (456) marks with the pid. A recreated worker (different pid) falls through and gets injected; a *failed* injection never records the pid, so it self-retries next turn (strictly better than the boolean even for today's behavior). `ensure_worker_pid/2`'s signature stays unchanged.
  - **View/API follow-through:** `AgentView.owner_view/1` (`lib/jido_claw/agent_view.ex:598`) reads `prompt_injected?` directly and would silently pin to `false`. Keep the *presentation* field name and derive it: `prompt_injected?: is_pid(Map.get(owner, :prompt_injected_pid))` — the pid stays internal to registry/router; views/tools expose only the boolean. The `handoff_owner` typespec (`agent_view.ex:67`) keeps `prompt_injected?: boolean()`. `JidoClaw.handoff_owner/2` (`lib/jido_claw.ex:516`) **keeps returning the raw pid-bearing owner map** — update its `@doc`/`@spec` wording to say so explicitly: an in-node runtime-truth accessor (pid-bearing, not serialization-safe), not a JSON/public projection; presentation layers derive booleans from it.
  - **Sweep every `prompt_injected?` reader/writer** (grep the repo, not just `put_owner` callers): known sites include `router_test.exs:172`, `registry_test.exs:47`, and the AgentView tests asserting `owner_view` output — update assertions to seed/expect the pid-keyed field while asserting the derived boolean at the view layer.
- **Unchanged** (stay `:permanent`): `lib/jido_claw.ex:165` and `lib/jido_claw/cli/repl.ex:67` (main/session agents).

## Accepted residuals (document in code, not fixed)

1. Tool process dying between `register` and the task's `attach_orchestrator` — microsecond window inside one tool call; the whole tool call fails with it.
2. The pre-existing benign race where a superseded orchestrator's late `mark_complete` lands on a re-engaged entry. The dangerous half (stale `:DOWN` erroring a fresh engagement) is closed by demonitor+flush; closing the benign half would require caller-validated `mark_complete` (rippling through specs, two tools, and two test stubs) for negligible value.
