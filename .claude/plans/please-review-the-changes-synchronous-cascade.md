### Phase 2 — S-M1: command-runner + interpreter recognition in the shell gate (FULL scope — user decision)
All in `lib/jido_claw/security/shell_command.ex`, as new sub-mappers in the `build/2` effects pipeline beside `crontab_effects/1`/`git_command_effects/1` (~:498-503):
- **Command-runners** `@command_runners ~w(xargs parallel watch entr chronic ts ssh su flock script strace unbuffer)` + `find` (special-cased). `runner_effects/1`: for a `%Command{cmd, args, arg_dyns}` whose `cmd` basename is a runner, emit `{:opaque, %{scope: :runner, reason: :command_runner}}` when any arg word resolves to a gated root (`git`, `crontab`) or an `@shells` member.
- **Interpreter one-liners** — the highest-value LLM evasion, since `-c` recursion is currently hard-scoped to `@shells` only. **Table-driven per interpreter (reviewer note), not one global rule** — a global `-c/-e/-r` misses Node `-p`/`--print` and would make Ruby `-r` (load library, which *does* run code) accidental rather than intentional. `@interpreter_eval_flags` maps each binary basename to its code-executing flags, e.g. `python`/`python3` → `~w(-c)`, `perl` → `~w(-e -E)`, `ruby` → `~w(-e -r)`, `node` → `~w(-e --eval -p --print)`, `deno` → `~w(eval)`, `bun` → `~w(-e)`, `php` → `~w(-r)`. `interpreter_effects/1`: an interpreter carrying one of *its* eval flags (incl. bundled/`=` forms) → `{:opaque, %{scope: :interpreter}}`. **Do NOT parse the code** — fail closed on the flag's presence. (`su -c 'git commit'` is covered by the runner path; a bare interpreter running a *script file* like `python foo.py` is not a one-liner and is a documented residual alongside `bash deploy.sh`.)
- **Piped / stdin interpreter execution (reviewer note 2).** `printf '…' | python`, `echo … | python -`, and `python -` read code from **stdin with no `-c`/`-e` flag**, so the eval-flag table above misses them — and the existing pipe gate only covers *bare shells* (`piped_bare_shell?`, `shell_command.ex:687`; interpreter recursion is shells+`eval` only, `:636-650`). Gate them (consistent with the full-scope decision — same evasion class as `python -c`): (a) an interpreter carrying a `-` / explicit-stdin arg, and (b) an interpreter that is a **pipe sink with no script-file arg**. **Implementation (reviewer note): do NOT route this through `pipe_structure/1`** — that feeds `structure_effects/1` (`shell_command.ex:547`), which flattens structure atoms to `{kind, %{}}` and loses the evidence. Instead add a **dedicated effect mapper** in the `build/2` pipeline near `parse_opacity`/`interpreter_effects` (it needs the `resolved` pipe-tagged list for the sink case, plus `commands` for the `-`-arg case) emitting `{:opaque, %{scope: :interpreter, reason: :stdin_interpreter}}` — same gating, richer evidence, cleaner structure semantics. **Residual boundary** (document): a piped interpreter *with* a script-file arg (`… | python foo.py`) ignores stdin and stays a script-file residual, same as `bash deploy.sh`.
- **Quoting fix (reviewer note 1).** `parallel 'git commit' ::: x` passes the template as a SINGLE argv word, so per-word `Path.basename` equality misses it — split each literal arg on whitespace before the gated-root match. (Cheap; also helps `xargs -I{} 'git commit'`.)
- **Dynamic args fail closed (reviewer note 5).** Any runner/interpreter with a non-empty `arg_dyns` (unresolved `$var`/expansion in argv) → `:opaque` — the analyzer can't prove the expansion inert (`find . "$predicate"`, `xargs $cmd`). For `find`: gate on `-exec/-execdir/-ok/-okdir` **OR** any dynamic arg (literal `find . -name git` with no exec form and no dynamics stays inert → no gate).
- **Documented residuals** (not gated — note in moduledoc + AGENTS.md so the `run_command` escape valve is a conscious choice): the `npx`/`nix run` family (run arbitrary packages — statically unknowable), interpreter *script-file* invocations, and the existing login-file-alias / script-file-indirection residuals.
- `:runner`/`:interpreter` are new **scopes**, not new effect kinds — zero ToolApproval wiring (`{:effect, :opaque}` is already in `run_command`'s require-patterns at `tool_approval.ex:158-177`, keyed by tool name — **not** in `run_command.ex`; traced end-to-end). There is **no `@type` scope union** — update only the moduledoc prose at `shell_command.ex:46-48`.
- The `:docker` shell-floor SKIP correctly suppresses all of this inside a provisioned microVM (verified `tool_approval.ex:259-276`) — no change there.
- Tests: new `describe`s in `test/jido_claw/security/shell_command_test.exs` (reuse `assert_opaque/2`, `gated?/1`): runner literal-bypass (`xargs`/`find -exec`/`parallel`/`ssh host git commit`/`su -c 'git commit'`/`flock … git commit`), the quoting case (`parallel 'git commit' ::: x`), interpreter one-liners (`python -c …`, `node -e …`, `node -p …`, `perl -e …`), piped/stdin interpreter forms (`echo … | python`, `… | python -`), dynamic-arg cases (`find . "$p"`, `xargs $cmd`), documented-FP gating (`watch git status`), negatives (`xargs ls`, literal `find . -name git`, `python foo.py` script-file, `cat data | python foo.py` must NOT gate). One `tool_approval_test.exs` case proving `run_command` + xargs-wrapped `git commit` → `{:pattern, :command}`, and unchanged docker-skip behavior.

### Phase 3 — C-H1 (partial) + C-H2: reclaim kill-cast + interleaving test
**Framing (per reviewer note 1): this is a MITIGATION, not a full fix.** The kill-cast stops the fenced executor from scheduling *further* reactor steps and continuing the workflow into the void (bounding the divergence from "the whole rest of the workflow" to "steps already in flight"), and closes the reclaim-owner routing gap. It does **not** interrupt already-started `async_nolink` steps — that is the accepted, documented orphaned-async limitation (`run_execution.ex:44-51`, `route_composer.ex:894-898`). The residual "run durably `:failed` while a side effect completed" is only fully eliminated by **per-step idempotency keys** (deferred; tracked in Out of scope), which Phase 1 (DB-clock) already narrows by removing the false-expiry contribution.
- `lib/jido_claw/orchestration/workflow_lease.ex`: `claim_one/1` captures the locked row's **pre-rotation** `claimed_by`; `claim_next/1`/`claim_run/1` return `{:ok, run, prior_owner}` (update `@spec`s — dialyzer will catch stragglers). Verified callers: exactly `reclaim_pooler.ex:99` + `workflow_recovery.ex:481`, plus **16** test assertion sites in `workflow_lease_test.exs`/`reclaim_pooler_test.exs` (mechanical `, _prior`) — update every direct caller/test.
- **Plumb `prior_owner` into top-level recovery (reviewer note 1).** The pooler currently matches `{:ok, run}` → `WorkflowRecovery.reclaim(run)` (`reclaim_pooler.ex:103,110`), and `reclaim/1` (`workflow_recovery.ex:174`) has no prior-owner arg. Add a **`reclaim/2` (or `reclaim_claimed/2`)** entry that takes `prior_owner`; the pooler matches `{:ok, run, prior_owner}` and calls it. Keep the existing `reclaim/1` for the **boot** path (no prior owner there). The **child** path needs no plumbing — `reclaim_child/1` calls `claim_run` locally (`workflow_recovery.ex:480`), so it captures `prior_owner` in scope.
- `lib/jido_claw/orchestration/workflow_recovery.ex`: after driving a reclaimed run to a **terminal** (failed plain runs in the `reclaim/2` plain branch; failed children in `reclaim_child/1`), best-effort kill-cast to `prior_owner`. Keep the cast at these **shallow** scopes — do NOT thread `prior_owner` down into `reconcile_one`/`fail_stranded`, which are shared with the boot-recovery path (no prior owner there). Reuse `Cancellation.resolve_kill_target/3` (already **public**) for routing; the actual dispatch arm `kill_if_live/1` (`cancellation.ex:248`) is `defp` — **promote it to a small public `cast_kill(target, run)` helper** and call it from both Cancellation and WorkflowRecovery (vs duplicating the ~10 lines). Composer **parents** are restarted, not killed (their own fence-kill covers the old executor). Idempotent by construction (`kill_local` no-ops on registry miss).
- Framing: the renew-fence sidecar self-kill already bounds a zombie to **one heartbeat**; the kill-cast merely shaves that window and covers the sidecar-dead / renew-hung cases — it is **opportunistic, not a correctness fence** (the fence is the token CAS).
- **Implementation rule (reviewer note 3): reload + confirm terminal immediately before the kill-cast.** `kill_local/2` kills by run-id from the *local registry* (`run_execution.ex:157-176`), so a cast issued after the run was resumed/re-registered would kill a fresh, legitimate executor. Only cast when the post-terminal reload confirms a terminal status — never after any branch that may have resumed the run. (Tenant-guarded + registry-miss no-op already make a *lost* cast harmless; this rule prevents a *wrong* kill.)
- Tests: extend `reclaim_pooler_test.exs` from the `:150` intra-node-task-death seam — executor left alive+registered, lease expired via `set_claim!`, `reclaim_once()`, assert `refute Process.alive?(executor)`. Plus **C-H2**: an interleaving test — rotate the claim to a simulated second owner mid-cancel and assert the cancel terminal lands once and the kill routes off the post-terminal reload (single-BEAM approximation; cross-node delivery is WS6).

### Phase 6 — O-M2: sensitive-only park deadline (with stale-message protection)
- `lib/jido_claw/route_composer/route_composer.ex`: when parking on a gate with `sanitize_sensitive_context` true and a `deadline_at_ms`, arm the timer with a **separate identity ref** — `Process.send_after` returns the timer ref, so it can't be carried *inside* its own message (chicken-and-egg). Use:
  ```elixir
  deadline_ref = make_ref()
  timer_ref = Process.send_after(self(), {:park_deadline, deadline_ref, child_run_id, case_id}, max(deadline_at_ms - now, 0))
  ```
  Store both in state (e.g. `%{deadline_ref: deadline_ref, timer_ref: timer_ref}` alongside `state.parked`).
- **Stale-message protection (reviewer note 2).** `state.parked` is singular by construction (solo-gate peeling; no tick fires while parked), so one timer slot is architecturally right. The handler ignores any `:park_deadline` whose **`deadline_ref`** (+ `child_run_id`) doesn't match the *current* stored slot — mirror the match-guard idiom at `route_composer.ex:1115`. Cancel with the stored **`timer_ref`**. A bare timer can otherwise fire after the gate resolved or after a *later* park and abandon the wrong case.
- **Authoritative deadline (reviewer note 4b).** Treat the durable `deadline_at_ms` as the authority: the handler **re-checks `past_deadline?`** rather than trusting the timer fired; arming already uses `max(deadline_at_ms - now, 0)` so an already-past deadline disposes immediately.
- **Cancel the timer at ALL FOUR `parked → nil` sites (reviewer note 4c)** — not only `{:gate_resolved}`: `fold_resumed_gate` (`:2010`) plus the three `terminalize_gate_disposition` clauses. `Process.cancel_timer(timer_ref)` + clear the slot; the `deadline_ref` match-check remains the real defense (cancel is belt-and-suspenders).
- **Deadline disposition must terminalize BOTH the child gate run and the parent (reviewer note 2, verified against `projection.ex:131`).** A parked *child* reaches terminal only via its own `run_abandoned`/terminal event (`next_status(:awaiting_approval, :run_abandoned) → :abandoned`); the parent's `finish/2`/`parent_terminal_notify` does NOT touch the child. `case_id` being nil (`recovered_case_id/2` can return nil, `route_composer.ex:2114-2116`) does NOT mean there is no case. So the handler must, keyed on `child_run_id`: look up `AgentCase.pending_for_run(child_run_id)` → if a pending case exists, `Cases.abandon/3` (the one-transaction child `run_abandoned` + case terminal `cancel_parked` uses); only if genuinely case-less, append the child terminal event directly. Then finish the parent via the composer's own terminal path. This guarantees the child never dangles `:awaiting_approval`.
- Re-arm on recovery re-park — specifically the `:awaiting_approval` arm of `resolve_recovered_gate/2` (~`:2139`), **not** `derive_park` itself; if already past deadline at re-park, dispose immediately (same `max(…, 0)` path).
- Docs: normal runs wait indefinitely by design — state it in the composer moduledoc and wherever the sensitive TTL ceiling is described (`FrontDoor`/triage config comment: the bound now truly covers parked time for marked runs).
- Tests: tiny-deadline marked run → parked run auto-abandons (child `:abandoned` + parent terminal); unmarked run with the same deadline stays parked; resolve-before-deadline cancels the timer AND a late stale `:park_deadline` (wrong `deadline_ref`) for the resolved child is ignored (no wrong-case abandon); a **nil-`case_id`-but-pending-case-exists** park still routes through `Cases.abandon` (child terminalizes); a **genuinely case-less** park hits the direct child-terminal-append branch. Assert the child run is never left `:awaiting_approval` in any deadline path.
