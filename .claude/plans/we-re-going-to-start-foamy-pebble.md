# Responsive App Shell (argus SPA)

## Context

First phase of implementing the Claude Design mocks (`ui/_mocks/project/Argus Explorations.dc.html` — the design source of truth): the **navigation frame both surfaces share**. Below `md` (768px) a custom fixed phone tab bar (Attention · Approvals · Threads · Projects, amber badges nearest the thumb); at `md`+ a fixed 196px shadcn Sidebar rail (brand → nav → PROJECTS → node-health footer). Design-only: pages stay stubs, no real data wiring, no theme toggle, no PWA.

**Mock visual sources**: tab bar lines 721–911; rail lines 3662–3932; light proof 10030–10783.

**Interview decisions (locked)**:
1. Rail nav is mock-exact: **Attention(3) · Approvals(3) · Threads · Runs("2 ◆") · Board** + PROJECTS section + node footer (atlas/desk ●, wren/laptop ●, basalt/"offline 2h" ○).
2. **Attention stub lives at `/`** (no `/attention` path). Smoke page moves to `/styleguide` (in shell, not in nav). New stubs: `/approvals`, `/threads`, `/board`.
3. Shell data is **static behind a seam**: `useShellData()` returns fixture counts/projects/nodes; later phases swap internals for real queries (`AWAITING_APPROVAL` runs are already queryable for the future Runs count).
4. Rail is **fixed, `collapsible="none"`**, width 196px — no trigger/Sheet/collapse UX.
5. **Dark stays hardcoded**; shell styles are token-pure so light works later by flipping the class.

**Architecture**: pathless layout route `src/routes/_shell.tsx` — future detail screens (transcript/gate/diff drop ALL chrome per the mock) live outside it. CSS-only responsive switch (`hidden md:flex` / `md:hidden`). Tab-bar icons are the mock's inline SVGs (19×19, stroke 1.6, `currentColor`, `aria-hidden`), not lucide. No top app bar — page headers are page content, out of scope.

**Reachability + honesty rules (review findings)**: every existing page stays reachable at BOTH breakpoints throughout; no focusable control is a no-op; no control lies about its destination:
- PROJECTS fixture rows render as **static text** (non-focusable, mono). One honest link row — **"All projects"** → `/projects` — closes desktop reachability (four rows all pointing at the same list would mislead and would all take `aria-current` on `/projects`). The `+` tile is decorative `<span aria-hidden>`.
- The Attention stub at `/` carries a temporary links list (View runs · View projects · **View board** · Styleguide) — covers phone access to `/runs` AND `/board` (neither has a tab by design) and `/styleguide` discoverability; removed when real pages land. During the transitional Step C, the smoke page (then still at `/`) gains a temporary "View board" link next to its existing View runs/View projects links so Board is phone-reachable from the moment it exists. Every temporary link's destination is test-asserted.

**Skills**: invoke `shadcn` skill before Step A (base-nova registry install); `design` skill before Step B/C (component build guidelines); `tanstack-router` skill before Step C (pathless layout + typed `linkOptions` conventions).

## Verified facts the plan rests on

- `SidebarProvider` is **mandatory** even with `collapsible="none"` (`Sidebar`/`SidebarMenuButton` call `useSidebar()` unconditionally). Its `useIsMobile` is happy-dom-safe.
- TanStack `Link` auto-applies `data-status="active"` + `aria-current="page"`. **Active matching includes search params by default** → every shell nav link sets `activeOptions: { includeSearch: false }`, the index link additionally `exact: true` (so `/?mock=empty` still marks Attention active and `/` doesn't stay active on `/approvals`). Style via `data-[status=active]:` / `group-data-[status=active]:`; never pass `isActive`.
- Nav config uses **`linkOptions()`** for typed `to` — which means it **cannot compile before its routes exist**: `shell-nav.ts` and its consumers (`app-sidebar.tsx`, `tab-bar.tsx`) belong to Step C, after the stub routes + codegen.
- base-nova sidebar registry deps (`separator, sheet, skeleton, tooltip, input, use-mobile`) are all `@base-ui/react` — **zero new npm deps**. Compose via `render={...}`, not Radix `asChild`.
- Known test breaks: `src/router.test.tsx` (both tests assert heading "argus" at `/`), `src/runs.test.tsx:369` (`findByText("View runs")`), `src/mocks/mock-mode.test.tsx:99` (`findByText("argus")` multi-matches once the rail renders on `/projects`).
- Nested-`<main>` hazard: `__root.tsx` renders `<main>`; the shell content wrapper must be the `main` landmark → root's becomes `<div>` (same classes, `min-h-screen` → `min-h-svh`). The smoke page (outside the shell until D) gets a **temporary `<main>` wrapper during C** so `/` never loses its landmark; D strips it again (it would nest inside the shell's `<main>`). Skip `SidebarInset`.
- Lint: `react/only-export-components` is ON for `src/components/` (only `src/routes/**` + `src/components/ui/**` exempt) → nav config + hook live in `src/lib/`; tab icons stay non-exported inside `tab-bar.tsx`. House style: explicit `.ts`/`.tsx` extensions on RELATIVE imports; `@/` alias imports stay extensionless (see `components/ui/badge.tsx`).

1. Run `codegen` (tsr generate) after every route add/move, before check/test — it rewrites moved `createFileRoute` ids in place; never hand-edit `routeTree.gen.ts`. Within C, codegen runs after route creation (C.3) and before `shell-nav.ts` typechecks.
