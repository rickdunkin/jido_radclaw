## Determination (TL;DR)

**The scan's one-line verdict ("status taxonomy + attention-sorted UX is the whole borrow") was half right, and the half that failed inverted usefully.** The taxonomy half delivers — as the **single-agent status contract** the sibling digs didn't cover: emdash EM2-1 owns the cross-agent *fold* + seen-flag, CCC CC1-2 owns the feed *kinds*/priority/suppression; muxara owns "what is THIS agent's state right now" — a small closed enum (`needs-input / working / idle / errored / unknown`) with needs-input **sub-typed by the kind of input needed** (Permission | Question), **plan-mode as an orthogonal modifier that is never a state** ("don't guess false" tri-state), an explicit precedence ladder (needs-input > errored > working > idle > unknown), and **asymmetric damping** (alarms flip instantly; only the working→idle decay is damped, by a wall-clock cool-off). Every signal it scrapes for, we already emit structurally — the native-signal mapping table is MX1-1's real payload. The attention-sorted-UX half inverts: muxara is the only project in the six that actually ships needs-input-floats-to-top, and it exhibits the exact churn defect CCC named when retracting sorting — **the keyboard selection ring binds to grid position, so a reorder silently moves your selection to a different session**. The badges-not-reordering verdict (CC2-1/EM2-1) is strengthened by its one counterexample, which also contributes the portable rule: *selection binds to identity, never position*. One unflagged find (the termic-sandbox pattern, smaller): the worktree lifecycle — creation delegated to Claude Code's own `-w` flag (the **agent-owned creation model**, a third shape beside traycer's host-owned and emdash/CCC's app-owned), and teardown **blocked on uncommitted changes** (the minimal honest busy-check, the missing middle of the CCC→traycer teardown spectrum). Everything else is detection plumbing and macOS desktop mechanics, skipped by the scan's standing rule.

**Why not adopt as a dependency**: (1) it is a macOS-only Tauri binary whose entire mechanism — tmux pane capture + regex classification at 1.5s — is exactly the detection plumbing the scan's standing rule excludes; our agent state is structured at the source. (2) It is a v0.1, effectively-solo, six-week-active product with zero frontend tests — spec-grade, not engineering-grade. (3) On every axis argus needs (persistence, orchestration, multi-device, auth, phone) it is a deliberate non-participant — by its own brief "a thin orchestration and observability layer" (`original-brief.md:22`). Its value is that within that thin scope it made several small, clean decisions worth writing down before we make the same ones from scratch.

## Tier 1 — read before the corresponding argus step starts

### MX1-1. The single-agent status contract: five states, sub-typed needs-input, modes as modifiers, asymmetric damping

**Recommendation**: BORROW-REFERENCE (the contract), landing as a FOLD-IN to CC1-2's attention module and argus step 2's card/schema design.

**Where in muxara**: the enums, verbatim (`src-tauri/src/session.rs:3-18`):

```rust
pub enum SessionState { NeedsInput, Working, Idle, Errored, Unknown }   // serde kebab-case
pub enum NeedsInputType { Permission, Question }                        // serde camelCase
```

Resolution is an explicit ladder, not last-writer-wins (`tmux/classifier.rs:172-201`): **NeedsInput > Errored > Working > (cool-off hold) > Idle > Unknown**. Sub-typing checks Question *before* Permission as "more specific" (`:92-108`; Question = `☐` checkbox marker or the select footer; Permission = four prompt patterns); the sub-type is emitted **only when the final state is NeedsInput** (`:205-209`). Plan-mode is **not a state**: an orthogonal `is_in_plan_mode: Option<bool>` (`:70-77, 130-146`) — two hard signals then a soft fallback, else `None` ("don't guess false", `:144-145`) — returned regardless of state (a NeedsInput result still reports plan-mode, test `:536-550`). Working = output-hash delta within a hard-coded 5s (`:148-160`); the only damping is on the *decay*: previous-Working + unchanged output holds Working for a wall-clock cool-off (`:191-196`; default 5 min, operator-tunable 0–60, `preferences.rs:58,77`) — alarms are never damped. `Unknown` = output lacks Claude markers (`:199`), rendered visually distinct (the only dashed border, `src/components/SessionCard.tsx:8-37`) and sorted with idle. Errored has a recovery check (a shell error followed by a fresh Claude TUI header is *not* errored, `:111-120`). Sub-types render as `"Needs Input · Permission"` / `"· Question"` (`SessionCard.tsx:76-84`); only Working animates (`StatusBadge.tsx:3-9`).

**What**: five rules, stated as a contract. (1) The per-agent status enum is small, closed, and severity-ordered, resolved by an explicit precedence ladder. (2) Needs-input is sub-typed by *what kind of input is needed*, and the sub-type exists only when the state does. (3) Modes are modifiers, never states — and a derived modifier is tri-state honest: detected, or unknown; never a guessed false. (4) `unknown` is first-class and visually distinct — "I can't read this" never masquerades as idle. (5) Damping is asymmetric: alarms raise instantly; only the working→idle decay is held.

**Gap in jido_radclaw** (verified 2026-07-03): we have **two unreconciled agent-status axes plus a third mini-model, and no sub-typing anywhere**. The child-agent axis (`AgentTracker`/`SwarmView`, and MCP `list_agents`) is binary-terminal — `:running | :done | :error`, no needs-input concept at all (`agent_tracker.ex:93,143-144`; `swarm_view.ex:118-120`; `tools/list_agents.ex:25`). The session axis (`AgentView`) has seven statuses (`agent_view.ex:28,59-66`) whose `:awaiting_approval` **collapses all three AgentCase kinds** — no Permission/Question/Plan distinction (`:557-569`) — and is **masked by `:running`** in the derive order (`:538-548`; a running trace wins even with a pending case). Forge phases are the third model, and its `:needs_input` carries the corpus-wide "Question" payload — a free-text prompt (`forge/harness.ex:661-663`, `session.ex:189`) — that reaches no live operator surface (`/forge` subscribes to the sessions topic only, `forge_live.ex:9`, so the blue badge goes stale; a `:failed` Forge session **drops out of `/forge` entirely**, active-only listing, `forge_view.ex:13-20,130`). Plan gates are indistinguishable beyond the literal kind text (`approvals_live.ex:59`); the shared badge helper defaults `:needs_input`, `:idle`, and `:hibernated` to the same blue (`core_components.ex:60-68`); LoopGuard's `:guardrail` Trace category is excluded from AgentView's default event projection (`agent_view.ex:55`). There is no MCP tool for the approval inbox (CC1-2a's `attention_status` remains the plan).

**Why it matters**: argus step 2's agent/worktree card needs **one status vocabulary across all the axes**, and this contract is the missing piece between EM2-1 (the fold across agents) and CC1-2 (the feed kinds): the per-agent enum both of those compose over. The mapping is native — muxara's Permission ≈ pending `AgentCase` `:tool_call`/`:irreversible_write`; Question ≈ Forge `:needs_input`'s prompt (and CC1-1's soft-block once built); the `:plan` gate ≈ a needs-input sub-type ("plan review"), while a composer plan-wave in flight ≈ the working-modifier analog of plan-mode; Working/Idle ≈ AgentView `:running`/`:idle`; Errored ≈ `:error`/run `:failed`/Forge `last_error`; Unknown ≈ `:agent_lost`/`:hibernated`/tracker-evicted — with the semantic caveat in OQ-2.

**Adoption sketch**: (a) at CC1-2's module design or argus step 2, whichever lands first: a unified derived `attention` field — `{state, sub_type, modifiers}` — computed from the three axes with muxara's ladder; `sub_type` from the pending case kind + Forge prompt presence. (b) Design around the AgentView masking rather than copying muxara's blocked-until-answered assumption: our ReAct loop *continues* past `approval_pending`, so needs-input must win the attention state even while the agent runs — the operator's decision is wanted regardless; how the card renders the concurrent activity is OQ-1. (c) Sub-type labels the muxara way ("Needs input · plan review"). (d) Modes-as-modifiers: "in plan wave", "compacting", "hibernated" ride beside the status, never replace it — and derived modifiers stay tri-state honest. (e) `unknown` handling per OQ-2.

## Tier 2 — adopt while building the named argus step

### MX2-1. The sorting counterexample: live-reorder shipped, churn defect included

**Recommendation**: FOLD-IN (CC2-1/EM2-1, argus step 2's list UX) — the fourth datapoint, and the one that closes the question.

**Where in muxara**: the backend returns a freshly attention-sorted list every poll — state priority then name, NeedsInput=0, Errored=1, Working=2, Idle=Unknown=3 (`store.rs:15-25,284-291`); the frontend renders it verbatim (no `.sort()` anywhere in `src/`; `SessionGrid.tsx:52-54`, `useSessions.ts:35-37`); *"Sessions that need your input are sorted to the top"* (`README.md:76`). No animation library — reorders are instant jumps. **The defect**: the emerald "focused" highlight is id-bound and survives reorders, but the keyboard selection ring is **positional** (`selected={index === selectedIndex}`, `SessionGrid.tsx:53`; `App.tsx:70-74` clamps out-of-bounds but never tracks identity) — when a state flip reorders the grid, the selection silently lands on a different session. Mitigations they did ship: idle+unknown share one priority tier with alphabetical tie-break, their own doc naming the reason — *"to maintain stable card positions"* (`architecture.md:123`); the 5-minute working→idle cool-off damps tier-flapping at the **state** level; a scroll-pause latch freezes data while you read (`useSessions.ts:23-33`).

**What**: the four-way record on attention-sorting, now complete: emdash never sorted (badges + notifications), CCC shipped sorting and retracted it as churn (CCC-182), termic badges on stable order — and muxara ships it, in the most favorable form factor the pattern will ever get (a compact always-on-top overlay with single-digit card counts, where glancing and jumping *is* the product), with real damping — and still manifests the churn cost as a concrete identity bug. One convergence worth a line: muxara damps **state** (the cool-off holds Working), CCC damps **order** (5-min hysteresis + demote-only stickiness) — independent arrival at minutes-scale, asymmetric, raise-fast/clear-slow damping, applied at opposite layers.

**Gap in jido_radclaw** (verified 2026-07-03): nothing attention-sorts or live-reorders today — every operator list is FIFO (`AgentCase` inbox `inserted_at :asc`, `agent_case.ex:249`), recency (`forge_view.ex:108`, CLI sessions), or registration order (SwarmView; AgentsLive unsorted, `agents_live.ex:82`) — so the rule arrives before the temptation does.

**Why it matters / Adoption sketch**: CC2-1's doctrine sentence gains its final clause — *badges on stable order, one hoisted bucket (`ended_blocked`), and if any surface ever does reorder or hoist, selection and focus bind to stable identity, never to grid position.* One sentence in the argus SPA's first list component; muxara's id-bound `focused` vs positional `selected` pair is the compact cautionary citation.

### MX2-2. Worktree lifecycle datapoints: agent-owned creation, dirty-check-blocked teardown

**Recommendation**: FOLD-IN (the argus step-1 reading stack: traycer TR1-3/TR2-1/TR2-2, emdash EM1-1/EM1-2/EM2-3, CCC CC2-3).

**Where in muxara**: creation never runs `git worktree` — when `use_worktree` (default **true**, per-project overridable, `settingsSchema.ts:3-17`) and the directory is a git repo, the bootstrap becomes `"{base_cmd} -w {sanitized_name}"`, delegating worktree creation to **Claude Code's own `-w` flag** (`commands.rs:219-249`; name sanitizer `git.rs:7-33`). The app then *recognizes* the CLI's convention after the fact: project-name derivation walks a `/.claude/worktrees/` path segment back to the parent repo's basename (`git.rs:38-65`); `is_worktree` = ".git is a file" (`git.rs:98-101`). Teardown: `kill_session` **hard-blocks if the worktree has uncommitted changes** (`git status --porcelain` non-empty → error, kill refused, no UI override; `commands.rs:265-309`, `git.rs:105-111`), else tmux kill + `git worktree remove` with warn-not-fail cleanup; the kill dialog warns the worktree will be removed (`SessionCard.tsx:282-286`).

**What**: two datapoints the reading stack lacks. (1) **The agent-owned creation model** — a third shape beside traycer (closed host binary owns worktree ops) and emdash/CCC (the app runs `git worktree add`): here the agent CLI owns creation and layout, and the orchestrator adopts its convention. The cost is visible in the code: hardcoded knowledge of someone else's path convention (`.claude/worktrees/`), which breaks the day the CLI changes it. (2) **Dirty-check-blocked teardown** — the minimal honest busy-check, filling the middle of the teardown spectrum: CCC delegates deletion to the agent via prompt (the anti-pattern, CC2-3) < muxara refuses to tear down dirty (one `git status`, hard block) < traycer's phased, busy-checked delete (TR2-1).

**Gap in jido_radclaw** (verified 2026-07-03): unchanged — no worktree functionality in the codebase (`security/shell_command/git.ex:150` remains the sole textual hit; argus OVERVIEW A.2); emdash EM2-3 (gate `git worktree` mutations in the shell analyzer) remains unshipped, noted at the termic dig and re-confirmed here.

**Adoption sketch**: nothing standalone; read with the stack at argus step 1. The dirty-check lands in the Worktree resource's destroy/archive action design (a busy-check before `git worktree remove`, composing with TR2-1's phased delete); the agent-owned model goes into the §3.1 design note as the named, rejected alternative — the answer to a future "why not just `claude -w`?" is its coupling cost, already paid once in muxara's `git.rs`. (Connective note, 2026-07-03: the Xantham dig, later the same day, supplied the far end of the same axis — worktree ops delegated *wholesale* to the harness's `isolation: "worktree"` param, observable result an unspecifiable merge-back story — so the delegation spectrum runs muxara (create only) → Xantham (everything), both arguing for orchestrator-owned ops; [XA3-2](../Xantham-system-blueprint/FEATURES-WORTH-BORROWING.md).) (Cross-corpus note, 2026-07-05: multica ships a middle shape on the same delegation axis — worktree creation is *agent-initiated* against a **daemon-owned** checkout endpoint (task workdirs start empty; the agent CLI calls in), keeping the mechanics orchestrator-owned while the trigger stays with the agent ([MC2-3](../../pms/multica/FEATURES-WORTH-BORROWING.md)); and the teardown spectrum this entry's dirty-check anchors gained a pms edition — orca force-deletes (branch included), myrlin record-delete strands, multica adds the full/orphan/artifact-only GC taxonomy ([MC2-2](../../pms/multica/FEATURES-WORTH-BORROWING.md)), symphony closes stranded PRs in `before_remove` ([SY2-4](../../pms/symphony/FEATURES-WORTH-BORROWING.md); [pms observation 11](../../pms/README.md)).)

## Tier 3 — garnish

### MX3-1. The calibration-corpus method — and the port-drift lesson

**Recommendation**: BORROW-RUBRIC (rides CC1-1's adoption; the Eval harness is the natural home).

**Where in muxara**: `spike/` is retained deliberately as the classifier's calibration dataset (`spike/README.md:1-14`): **43 stripped fixtures (86 files, paired `_stripped` + `_ansi`) of real captured Claude Code TUI** across six categories (idle 5, working 10, permission 10, question 5, plan-mode 10, errored 3), captured by a documented script (`capture.sh:30-33` — `tmux capture-pane -p [-e] -S -200` at 2s intervals), pinned by table tests over every fixture per category plus ~12 hand-written temporal/orthogonality cases (`classifier.test.ts:46-298`); `findings.md` records the discovery process (a measured 2.54 flickers/min motivating the debounce, `:242-271`). **The lesson half**: the Rust port kept the regex set byte-identical but silently swapped the damping *mechanism* — the spike's poll-count debounce (hold Working 2 polls, `classifier.ts:132-137`) became production's 5-minute wall-clock cool-off — leaving the ported `consecutive_idle_count` field **vestigial** (`classifier.rs:66`, never read) and the "debounce" naming stale. The fixtures came along; the temporal tests weren't re-derived — the corpus pins the patterns but not the dynamics.

**What / why it matters**: the method — capture real paired fixtures, categorize by intended classification, pin with table tests, keep the corpus for recalibration — is exactly the test discipline CC1-1's soft-block detector wants (a fixture corpus of real terminal runs that ended in questions vs. ended done; CCC ships detector tests but no captured corpus), and it fits `JidoClaw.Eval` natively (case files under `test/jido_claw/eval/`). The drift half is the porting lesson: **port the tests with the mechanism, or the fork is silent** — our LoopGuard port (thresholds verbatim + an Exec/Turn-driven contract test) is the done-right local precedent to keep citing.

**Gap in jido_radclaw** (verified 2026-07-03): the Eval harness exists (`eval/case.ex`, `eval/run.ex`) but has no terminal-output fixture corpus; CC1-1 is queued (CCC's suggested first wave) and will want one at build time.

### MX3-2. Card and list garnishes

**Recommendation**: BORROW-RUBRIC — four one-liners for the argus SPA card, recorded so they don't need rediscovering:

- **Two-zone card**: orientation (name, project, branch, worktree badge, "state · recency") above context (live output tail), with idle/unknown cards' context collapsed by default (`showIdleOutput: false`; `SessionCard.tsx:220-241`). The argus worktree card wants the same fold — badges always, tail on demand.
- **Label what you measure**: muxara's "Working · 2m ago" is time-since-output-changed, not time-in-state (`timeAgo(lastChangedAt)`, `SessionCard.tsx:64-74`) — honest because the label doesn't overclaim. Our event-sourced statuses can show true state duration; whichever is shown, name it correctly.
- **Don't yank content the operator is reading**: scrolling a card's output pauses data refresh for 5s (`useSessions.ts:23-33`). The argus live-tail component inherits the rule — freeze on scroll, resume on idle.
- **Deterministic project hash-tint** (8 colors, `SessionCard.tsx:45-62`): visual project affinity with zero grouping machinery — cheap and effective for the flat-list phases of the argus UI before real grouping lands.

## Open questions

- **OQ-1**: When MX1-1's unified attention state meets our non-blocking approval semantics — a ReAct agent *continues* past `approval_pending`, unlike muxara's blocked TUI — does the card render needs-input, or running-with-a-needs-input-badge? Lean: needs-input wins the **state** (it drives the fold, the feed, and pushes — the operator's queue is the point), live activity renders as a modifier. Decide when CC1-2's module lands.
- **OQ-2**: `unknown` ranks last in muxara (sorted with idle, dashed border) but termic TM2-5 says ambiguous states fail **toward** attention. Both are right in their own semantics: muxara's unknown means "this pane isn't a Claude session" (correctly boring); termic's means "my agent's state is unreadable" (correctly alarming). Our equivalents (`:agent_lost`, `:hibernated`, tracker-evicted-with-a-live-run) are the second kind. Lean: follow termic for agent-shaped unknowns; reserve muxara's boring-unknown for genuinely foreign things (a Workspace with no live worker is not an alarm). Decide inside MX1-1's ladder.
