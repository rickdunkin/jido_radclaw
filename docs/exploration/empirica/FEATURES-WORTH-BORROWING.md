# Features Worth Borrowing from Empirica

Exploration notes — not a plan, not a commitment. **Inventory: 2026-07-02**, against empirica @ `9e81ce6e` (v1.12.10, same-day) and jido_radclaw @ `92601305` (main). Cites are firsthand reads of both trees, accurate to within a few lines.

Source: `~/workspace/research/empirica` — [EmpiricaAI/empirica](https://github.com/EmpiricaAI/empirica), MIT (David S. L. Van Assche / Empirica AI GmbH). Self-description: *"Epistemic infrastructure for AI — measurement, memory, and calibration across sessions."* Python ≥3.10; ~513 files ≈ 192k LOC plus a separate `empirica-mcp` package (80 tools, all thin CLI mirrors); 260 test files; ten months of 300–450 commits/month. Its shape matters more than its size: empirica is an **exoskeleton for a third-party agent** — a ~180-verb CLI over SQLite + git-notes + Qdrant, bolted onto Claude Code through hook subprocesses (`PreToolUse` gate, compaction capture/restore pair, statusline respawned every 5s). It owns no runtime, no model loop, no scheduler.

**Reading posture for this one: code-first, docs-second.** More than any prior exploration subject, empirica's architecture docs describe a system its code has partially demoted or disabled. The marketed vector-threshold gate returns advisory-allow on failure (`plugins/claude-code-integration/hooks/sentinel-gate.py:3604-3619` — the reference doc still says DENY); the "cognitive immune system" is hard-disabled after eroding the facts it should have reinforced (`cli/command_handlers/artifact_log_commands.py:854-876`); the temporal codebase model's facts/constraints tables have no producer, its relationships no reader. Every entry below traces the read path first.

The core idea, in one sentence: make the agent's knowledge state explicit and durable — bracket each unit of work with self-assessed measurements (PREFLIGHT → CHECK → POSTFLIGHT), force investigation before mutation, persist typed epistemic artifacts (findings / unknowns / dead-ends / mistakes) that outlive the context window, and calibrate stated confidence against deterministically-observed outcomes.

Companion docs: this inventory lands on territory adjacent explorations already mapped — [optimal-engine](../optimal-engine/FEATURES-WORTH-BORROWING.md) (epistemics-flavored memory, where our bitemporal Facts + RRF recall already won the comparison), [gepa](../gepa/FEATURES-WORTH-BORROWING.md) (eval sets + reflection: GP1-2's EvalRecord is the natural consumer of the calibration records proposed here), [camus](../camus/FEATURES-WORTH-BORROWING.md) (deterministic verification as final authority — overlaps EM2-2), [osa](../osa/FEATURES-WORTH-BORROWING.md) (compaction/continuity slots), and [alp-river AR-9](../alp-river/FEATURES-WORTH-BORROWING-V2.md) (premises threading + plan arbiter — the composer seams several entries ride). The [unadopted-next-five queue](../../plans/unadopted-next-five/README.md) item 5 (deterministic eval harness) is the trigger surface for EM1-2. First inventory — no `UNADOPTED-IDEAS.md` rollup yet.

## Why not adopt empirica as a dependency

1. **Runtime mismatch, squared.** Pure Python *and* subprocess-per-everything: every hook shells `empirica <verb>`, the MCP server shells the CLI, the statusline cold-starts Python + opens SQLite every 5 seconds. Inside the BEAM these are function calls.
2. **It is an exoskeleton for an agent it doesn't control — we own the organism.** A large fraction of its complexity (session-identity reconstruction via `active_work_<uuid>.json` files and tmux-pane suffixes, hook timeout budgets, fail-open-on-crash, self-scheduling one-shot loops through systemd/launchd, a Monitor-wake bridge for dormant sessions) is heroic compensation for wrapping a third-party, out-of-process, dormant-between-turns tool. jido_radclaw has OTP process identity, a supervised runtime, a cron scheduler, and a signal bus; the entire compensation layer evaporates.
3. **Persistence mismatch.** SQLite + git-notes + JSON triple-write with graceful-degradation glue, and Qdrant that silently degrades to hash-1536 pseudo-embeddings when no provider is configured (`empirica/core/qdrant/embeddings.py:114-117`). We event-source to Postgres, embed via a real provider with an explicit FTS fallback, and get resume from `WorkflowEvent` projection.
4. **The read-path problem.** The recurring failure shape in this codebase is schema + repository + scorer with a thin or absent consumer (codebase facts/constraints never populated, relationships never read, three drift checkers with zero callers, an orphaned flow-state metric). Bridging to it would mean inheriting surface that even its own workflow doesn't read.
5. **The marketed core is disavowed by its own code.** The epistemic-readiness gate — the headline — blocks on *structure* (no PREFLIGHT, no CHECK, rushed timing), not on the 13 vectors; the vector threshold itself returns `("allow", "ADVISORY: …")` on failure. What actually works in empirica is deterministic ritual enforcement, and we already have a stronger form of that (composer data-DAG + locks + human gates).

## Tier 1 — High Impact

### EM1-1. Negative knowledge as first-class memory, re-surfaced at the decision point

**Recommendation**: BORROW-PATTERN.

**Where in empirica**: `empirica/data/schema/projects_schema.py:128` (`project_dead_ends`: **`approach` NOT NULL, `why_failed` NOT NULL**, impact, goal/transaction FKs) and `:104` (`project_unknowns`: `is_resolved`, `resolved_by`, `resolution_finding_id` — resolution provenance links the unknown to the finding that answered it, wired via `resolve_unknown`, `breadcrumbs.py:339`). Creation is explicit LLM-called CLI verbs (`deadend-log`, `unknown-log`, `unknown-resolve`) with content-hash + similarity dedup on write. Surfacing is the payoff: `check_against_patterns` (`empirica/core/qdrant/pattern_retrieval.py:874-941`) semantically matches the **current approach** against stored dead-ends at the CHECK gate (threshold 0.7) and returns `{approach, why_failed, similarity}` matches; PREFLIGHT retrieval returns task-relevant dead-ends (`:733-744`); the post-compact re-injection and the MEMORY.md hot cache both carry a dedicated "Dead-Ends (avoid re-trying)" block (`empirica/core/memory_manager.py:259-263`). The ranking that orders all of this deliberately weights negative knowledge nearly as high as positive: `TYPE_CONFIDENCE = finding 0.9, dead_end 0.85, mistake 0.85, goal 0.75, unknown 0.6` with a 24h-half-life recency decay (`plugins/claude-code-integration/hooks/epistemic_summarizer.py:15-35`) — "cost was paid, lesson is real."

**What**: A structured failure ledger and open-question ledger, designed to be *pushed at the agent at the moment it is about to choose an approach* — not merely searchable.

**Gap in jido_radclaw**: Memory has no kind/category at all — the `remember` tool's `type` (`fact, pattern, decision, preference`, free-form string, `tools/remember.ex:42-47`) is coerced into `tags` (`memory.ex:341-364`); nothing models "tried X, failed because Y" or "open question blocking Z" (greps for dead-end/failed-attempt/anti-pattern/unknown across `lib/` come back empty). The Solutions subsystem is the *success* dual only: a failed verification flips `verification.status` to `"failed"` on the same solution row and increments the agent's `solutions_failed` reputation counter (`solutions/resources/reputation.ex:24-35`) — it never becomes retrievable "don't retry this approach" knowledge. The nearest primitive is the consolidator-authored `Memory.Link` `:contradicts` edge between two positive facts (`memory/resources/link.ex:5-12`). And retrieval is pull-only: Facts reach the model only when the agent chooses to call `recall`; nothing volunteers "you tried this before."

**Why it matters**: Re-exploring failed approaches is a real, expensive agent failure mode — the exact one the platform's loops manufacture evidence for: fixer/re-review iterations, `route_verify_failed` terminals, rejected plan gates, abandoned sketches. Today that evidence terminates in `WorkflowEvent` rows nothing re-reads (the same dead-endedness the gepa doc flagged for scorer diagnostics). Empirica's implementation of this — unusually for that codebase — is wired end-to-end and live, which is decent evidence the shape works.

**Adoption sketch**: (a) Add a `kind` to `Memory.Fact` (`:fact | :dead_end | :unknown | ...` — see OQ-1 for kind-vs-tags) with typed payload conventions: dead_end carries `{approach, why_failed}`, unknown carries `{resolved_by_fact_id}` on resolution; pin the JSONB round-trip shapes. (b) Extend the `remember`/`recall` taxonomy and the consolidator prompt so clustering treats negative knowledge distinctly (never merged into positive facts; `:contradicts`/`:supersedes` links preferred). (c) Surfacing, the actual point: the composer's `planner` stage gets a scoped dead-end/unknown lookup rendered into `:extra_context` — the `PremisesContext` block (`route_composer/premises_context.ex`) is the exact precedent for "small structured block, worker told what to do with it"; boost `kind: :dead_end` in `recall` ranking (EM3-3 weights). (d) Producers: start explicit (the fixer/reviewer templates' doctrine instructs logging a dead-end when an approach is abandoned) plus consolidator-mined from terminal `WorkflowEvent`s; automatic emission on `route_verify_failed` is OQ-2.

### EM1-2. A confidence-calibration ledger: Brier decomposition over stated-vs-grounded outcomes

**Recommendation**: BORROW-PATTERN.

**Where in empirica**: `empirica/core/post_test/dynamic_thresholds.py:188-248` (`compute_brier_decomposition` — Murphy (1973): `BS = Reliability − Resolution + Uncertainty`, binned, correct) and `:135-186` (`compute_check_brier` — the cleanest falsifiable loop in the system: the AI optionally predicts `P(check passes)` per compliance check at PREFLIGHT; the check runs; `(predicted − actual)²` is scored against ground truth). Authority is deliberately bounded: only the **Reliability** term (calibration error) inflates the auto-proceed thresholds, capped at +0.05, damped by `min(1, n/20)`, floor of 5 samples per phase (`:339-364`). The grounded evidence side (`collector.py`/`mapper.py`) reads pytest reports, executes ruff/radon/pyright, shells git — with per-source quality weights and an insufficient-evidence gate (coverage < 0.3 ⇒ "self-assessment stands"). Two design rules ride along: grounded scores are **informative, never authoritative** (`grounded_calibration.py:17-36` — "a drift indicator, not a grade"), and calibration warnings are **deliberately not surfaced to the agent** ("answer-key for gaming self-assessment," `pattern_retrieval.py:765-768`).

**What**: A durable ledger of (stated confidence, deterministic outcome) pairs, periodically decomposed so *calibration error* is separated from *resolution*, with tightly bounded write authority over behavior.

**Gap in jido_radclaw**: Calibration does not exist — greps for `brier`/`calibrat`/`self_assess`/predicted-vs-actual across `lib/` return zero. The forward half is already flowing: certificates carry `confidence` 0.0–1.0 (`reasoning/certificates.ex:301-389`), it is persisted on every outcome row (`reasoning/resources/outcome.ex:200`, `reasoning/telemetry.ex:283`) — and then never read again (write-only; `Statistics` aggregates execution `status` only, `reasoning/statistics.ex:34-70`). Reviewer findings carry confidence tags; the doctrine `confidence_tagging.md` makes workers label claims `likely`/`unsure` — qualitative, never checked. Worse: one uncalibrated confidence already has *write authority* — a certificate's `c` becomes `c * 0.85` of the verification term in Solution trust (`solutions/trust.ex:143-166`), 35% of the trust score.

**Why it matters**: This is the rare borrow where our substrate is *stronger than the source's*: empirica struggles to get grounded observations (it reads a pre-existing pytest JSON; half its declared cybersec checks have no runner), while jido_radclaw already produces deterministic outcomes on every axis — verify waves, Forge runs, `PatchQuality` checks, and the queued eval harness ([unadopted-next-five item 5](../../plans/unadopted-next-five/README.md)) whose trigger fires with AR-9. A calibration ledger tells us, per template/strategy/lens/task_type, whether stated confidence means anything — which directly conditions how much the `c * 0.85` trust input, the arbiter's decision memos, and gepa's future eval scores should be believed. The (prediction, outcome, feedback-ref) row is also exactly the GP1-2 `EvalRecord` shape — one schema serves both programs.

**Adoption sketch**: (a) `CalibrationSample` Ash resource: `{surface, key (template|strategy|lens|task_type), predicted (float), outcome (boolean), refs (trace/workflow_event/outcome ids)}` — writers: `verify_certificate` (certificate confidence vs subsequent deterministic verification), composer verify waves (reviewer finding confidence vs fixer-confirmed/gate-dismissed), eval-harness runs when they land. (b) A pure `Reasoning.Calibration` module (~150 lines): Brier decomposition per key over a window; property-test the decomposition identity. (c) Consumers, deliberately staged: `/strategies stats` + dashboard read-model first (read-only); any write authority later and bounded, mirroring the cap-and-damp rule — e.g. an `AutoSelect` tie-break input or a calibration-discount on the `c * 0.85` trust term (OQ-4). (d) The check-Brier variant as the cleanest first producer: an optional planner-emitted `predicted_outcomes` map over the route's verify lenses (premises seam carries it; typed signal), scored when the review waves land. Design laws DL-3/DL-4 apply: never inject an agent's own calibration into its prompt; refuse to score below a sample floor.

## Tier 2 — Useful, gated on a design decision

### EM2-1. Retrieval-before-edit: file-scoped memory surfacing at tool dispatch

**Recommendation**: BORROW-PATTERN, after EM1-1.

**Where in empirica**: `empirica/core/file_relevance.py:41-110` (`get_file_relevant_artifacts` — LIKE over six artifact tables for basename + relative path, recency-sorted, per-table caps), wired as a PreToolUse nudge in `sentinel-gate.py:3240-3276`: before the agent edits a file, prior findings/decisions/dead-ends/mistakes *mentioning that file* are injected. No ML, one query.

**What**: Retrieval keyed by the **action**, not by the agent remembering to ask. The measurement-internals sweep rated this the smallest, highest-leverage mechanism in the codebase.

**Gap in jido_radclaw**: `recall` is agent-initiated only; the prompt snapshot is deliberately frozen (`agent/prompt.ex:224-226`); nothing keys memory to files at all.

**Why it matters / the gating decision**: With only generic facts in the store this is noise; with EM1-1's dead-ends and decisions it becomes "the last three sessions' scar tissue about this exact file, at the moment of touching it." The design decision is placement: a read-only stage in the shared `Tools.Action` pipeline for `edit_file`/`write_file` (result-augmentation — append a bounded "Prior notes on this file" section to the tool *result*, so it composes with redaction/shaping and can never block), vs. planner-stage-only injection (cheaper, composer-scoped). Budget one lexical query (the trigram/FTS columns already exist), cap the block, `enabled?: false` until hit-rate telemetry justifies it.

### EM2-2. Typed success criteria evaluated against an evidence bundle

**Recommendation**: BORROW-PATTERN, deferred behind the camus verification decisions.

**Where in empirica**: `empirica/core/goals/types.py:57-99` (`SuccessCriterion{description, validation_method ∈ completion | quality_gate | metric_threshold, threshold, is_required, is_met}`); `empirica/core/post_test/criterion_evaluators/__init__.py` (registry dispatch keyed on `validation_method` → evaluator runs against the POSTFLIGHT `EvidenceBundle` → persists `is_met` → failing required criteria emit `iteration_needed` + a suggested `next_transaction`). Two honesty details worth copying and one trap: zero-subtask goals produce a **"no signal" skip**, not a fake pass; quality-gate criteria bind to a *named collected metric* and skip cleanly if absent; and `metric_threshold` is schema-validated but has **no registered evaluator** — accepted and silently never evaluated. Same trap at larger scale in the domain registry: cybersec checklists declare `semgrep_full`/`gitleaks`/`sbom_audit` with no runner registered, so they runtime-fail as "not registered" (`compliance_loop.py:153-164`).

**What**: "Done" as data — machine-checkable acceptance criteria bound to evidence, with honest skips, instead of a boolean.

**Gap in jido_radclaw**: Composer routes end via reviewer-clean/human-gate judgment; there is no per-run declared acceptance contract a deterministic evaluator checks. The eval harness covers *test-time* assertions, not *run-time* acceptance criteria.

**Why deferred**: camus's "deterministic verification as the final authority" adoption path covers overlapping ground — don't build two acceptance machineries. And where criteria live (front-door premises? plan artifact? skill YAML?) is a real design fork. Smallest slice when triggered: a `criteria:` block on the plan artifact (planner emits, plan-gate displays, a route-end evaluator stage checks the quality-gate-shaped ones against Forge/test output and stamps results into the terminal event). Carry the two rules: **no-signal skips stay visible as skips**, and **never declare a check you haven't implemented** (their unimplemented-check trap).

## Tier 3 — Watch / polish

- **EM3-1. Sub-agent rollup gating + delegated-work accounting — watch.** `plugins/claude-code-integration/hooks/subagent-stop.py:98` (child tool-calls added to the parent's counters as `delegated_tool_calls` — "without this, spawning subagents is a blind spot in the parent's autonomy loop") and `:248-418` (child findings scored `confidence·novelty·relevance`, Jaccard-deduped against the parent's existing findings, budget-gated before entering parent state). We already track per-agent tokens/tools with lineage (`agent_tracker.ex` — `parent_agent_id`, per-agent `tokens`/`tool_calls`), AR-9's arbiter is the judged-merge for composer lenses, and there is no conversation-axis budget for the counting half to feed. Trigger: an observed parent-context-flooding incident from swarm spawns, or a conversation-axis budget becoming a goal. The companion "investigation-proportionality budget" (prompt-armed, dispatch-enforced read cap, `sentinel-gate.py:3806-3811`) files under the same trigger.
- **EM3-2. Session-end consolidation trigger — small.** Empirica curates its hot cache at session end; our consolidator is a 6h cron (`config/config.exs:479-481`), so the next session's Blocks can trail the one just finished by hours. Cheap increment: enqueue a scoped consolidation tick on session close (leader-gated, same idempotent machinery). Trigger: evidence that the 6h staleness actually bites — don't add a second cadence on principle.
- **EM3-3. Ranking defaults for artifact surfacing — rides EM1-1.** `weight = impact × type_confidence × recency_decay` with `dead_end 0.85 ≈ finding 0.9 > goal 0.75 > unknown 0.6` and a 24h half-life (`epistemic_summarizer.py:15-35`) is a sane, field-tested starting point for EM1-1's recall boost and the consolidator's block ordering. Piquant detail: empirica's own *durable* MEMORY.md writer doesn't use its documented formula (impact-only sort; the full-formula writer is dead code) — we'd be using their design where they didn't.

## Design laws worth recording (no build — checklist entries)

- **DL-1. The release-path invariant.** *A gate must never block the action that clears it.* Empirica evaluates an always-open set of recovery/measurement verbs before every gate (`sentinel-gate.py:925-963`). Our human-decided gates satisfy this trivially (the operator, not the agent, clears them) — but any future *automated* gate (an EM1-2-informed readiness check, a budget denial) must re-check it or it deadlocks.
- **DL-2. Nudge in context, enforce at dispatch.** Their comment, verbatim: *"Soft text blocks were empirically insufficient (model ignored them); this is the runtime constraint that makes the discipline real"* (`sentinel-gate.py:3806-3810`). Independent field confirmation of the house posture — composer locks, tool-approval, budget gates all enforce in the runtime, never in prose.
- **DL-3. Similarity is not contradiction.** The "cognitive immune system" decayed related knowledge on keyword/cosine overlap with no opposition predicate — so *confirmatory* findings eroded the very facts they confirmed ("autoimmune erosion"), and both decay paths are now hard-disabled pending "a real opposition predicate" (`artifact_log_commands.py:854-876`). Applies verbatim to our consolidator's update/invalidate proposals and any future automation over `Link :contradicts`: contradiction must be an explicit judgment (the consolidator's LLM + the link's `reason` field is one), never an embedding-distance side effect.
- **DL-4. Anti-gaming: don't hand the agent its own scorecard.** Calibration bias warnings are deliberately withheld from the agent — "answer-key for gaming self-assessment" (`pattern_retrieval.py:765-768`). Bears on EM1-2's consumer design and on whether `trust_score` ever enters prompts.
- **DL-5. Port by read-path.** The recurring empirica failure shape: schema + repository + scorer, no consumer (codebase facts/constraints never populated, relationships never read, three drift checkers with zero callers, orphaned flow-state metric, dead full-formula MEMORY writer). Before building any measurement, name the module that reads it into a prompt or a decision — or don't build it.
- **DL-6. Fail-open is a policy decision, not a default to inherit.** Their gate fail-opens on any internal error unless an env flag says otherwise (`sentinel-gate.py:3854-3863`) — a firewall that opens when it crashes. Our tool-approval fails closed; keep making that choice explicitly per gate.

## Skip / Already Covered

- **13 epistemic vectors + the CASCADE bracket as gate inputs — SKIP.** Honor-system self-reported floats (schema validates range and nesting, nothing checks score-vs-rationale); the gate consults only `know`/`uncertainty` and its threshold returns advisory-allow on failure (`sentinel-gate.py:3604-3619`). Empirica itself calls it "a measurement system, not a rules-based gate." Our per-claim `likely`/`unsure` doctrine tagging is the leaner analog already shipped; EM1-2 is the part of this worth having — the calibration, not the vectors.
- **Sentinel structural rituals (investigate-before-act, rushed guard, closed-loop guard) — ALREADY-COVERED.** The composer's data-DAG + locks enforce researcher → plan → human-gate → implementer *unconditionally* (`route_composer/catalog.ex:138-141` — `implementer` locks `until: "plan-approved"`); empirica's version is a timestamp-and-count heuristic on an agent it can't structure. Their noetic/praxic firewall (180 lines of `SAFE_BASH_PREFIXES` heuristics, because a hook can't see tool semantics) is what `ShellCommand.analyze/1`'s fail-closed effect analysis already does with real structure.
- **MEMORY.md hot cache — ALREADY-COVERED.** Block tier is prompt-injected and consolidator-curated (`agent/prompt_sections.ex:11-32`; LLM curation with audit counters) — richer than their wired writer, which is an impact-only sort that ignores their documented ranking formula.
- **Compaction survival pair (pre/post-compact hooks, state-routed recovery) — ALREADY-COVERED.** The Compactor's durable per-agent snapshots + summary re-injection and the event-sourced composer resume are the in-process versions; their pair exists because they don't own the summarizer. The osa doc already covers our remaining compaction-degradation gaps.
- **Loops / scheduler / listener / instance identity — SKIP.** Self-scheduling one-shot crons, systemd/launchd abstraction, wake-from-idle bridges, `active_work_<uuid>.json` identity reconstruction: all compensation for a dormant, scheduler-less host. OTP + cron scheduler + signal bus collapse the entire subsystem.
- **Cross-AI mesh / SER / practice model — SKIP.** The interesting layers (Cortex, ECO extension) are proprietary; the open part is git-notes mailboxes + pollers. Cluster + signal bus + `network_share` cover the local story; revisit only if cross-org agent federation becomes a goal.
- **MCP server — SKIP, with inverse validation.** Their own docstring: tools "route to CLI via subprocess. **No epistemic middleware**" — gating bolted outside. Ours gates *at the tool boundary* (`Tools.Action` wraps every tool including MCP proxies); empirica is the argument for why.
- **Temporal codebase model / entity graph / drift checkers / flow-state — SKIP.** Regex extraction; facts + constraints tables have no producer, relationships no reader, staleness never surfaced ("knows what's stale" is aspirational); the CRM-ish entity graph is real but out of scope; `doc_code_integrity`/`cli_doc_validator`/`structure_health` have zero consumers. DL-5 is the takeaway.
- **Statusline — SKIP.** The REPL status bar already shows the operational truth (model, tokens/context %, cost, agent count); an epistemic-% segment would render exactly the self-reports we're declining to collect. (Their composite, for completeness: `0.40·know + 0.30·(1−uncertainty) + 0.20·context + 0.10·completion`.)
- **Track-1 self-referential Bayesian beliefs — SKIP.** The agent grading itself with no ground truth; half its public API (`apply_calibration_to_vectors`, bias-correction loaders) is never called. EM1-2's grounded track is the defensible half.
- **Issue auto-capture / lessons hot-cache — ALREADY-COVERED / SKIP.** Trace events + normalized tool errors cover capture; their in-memory lesson graph is write-heavy with no wired reader (the live path is Qdrant retrieval).

## Open questions

- **OQ-1 — Kind vs. tags.** Does negative knowledge land as a first-class `kind` attribute on `Memory.Fact` (migration + typed payload + recall-boost SQL) or as a validated tag vocabulary over the existing `tags` array (no migration, weaker typing)? The bidirectional present-nil trap and JSONB round-trip rules apply either way.
- **OQ-2 — Dead-end producers.** Explicit (doctrine instructs fixer/reviewer to log abandoned approaches) + consolidator-mined from terminal `WorkflowEvent`s, vs. automatic emission on `route_verify_failed`/fixer-exhaustion. Automatic is tempting but risks low-quality entries; empirica's write-time dedup + required `why_failed` is the floor either way.
- **OQ-3 — First calibration producer.** Certificate-confidence-vs-verification (data already flows; joins existing rows) or planner check-Brier over verify lenses (cleanest falsifiable contract; needs the premises seam to carry predictions)? Leaning certificates-first for zero new prompt surface.
- **OQ-4 — Calibration write authority.** Does the ledger ever adjust behavior (AutoSelect tie-break, a calibration discount on the `c*0.85` trust term), or stay a read-only dashboard? If it writes: adopt the cap-and-damp bound (+0.05-equivalent, sample-count damping, floor-of-n) rather than proportional control.

## Bottom line

Empirica is the first exploration subject whose most valuable export is its *scar tissue*. As a dependency it is a non-starter (wrong runtime, exoskeleton architecture, persistence we out-class), and its headline machinery — the 13 vectors, the epistemic gate — is quietly advisory in its own source. But it has shipped, live and wired, exactly two contracts that land on slots verified empty here: **structured negative knowledge pushed at the agent at the decision point** (EM1-1 — the failure dual of our success-only Solutions store, with producers our composer loops already manufacture), and **a bounded-authority calibration ledger** (EM1-2 — Murphy Brier over stated-vs-grounded pairs, which our verify waves and queued eval harness can feed better than empirica ever could). Around those two sit six checklist-grade design laws (DL-1..6) — release-path invariant, enforce-at-dispatch, similarity-is-not-contradiction, anti-gaming, port-by-read-path, explicit fail-policy — each one paid for by a documented empirica failure, each one directly applicable to the consolidator, the gate family, and the measurement work already queued. Take the two contracts, record the six laws, skip the rest.
