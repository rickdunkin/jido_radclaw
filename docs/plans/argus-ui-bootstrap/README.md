# Plan: Argus UI Bootstrap — the GraphQL surface, the `ui/` client, and the loop between them

*Phased build plan — not a commitment. Drafted 2026-07-10 against `jido_claw`
0.6.4.*

This program builds the **substrate underneath FLOW §13 slice 1**: the GraphQL
read surface, the React SPA scaffold, the schema→codegen→render loop with its
drift guard, node-served deployment, the live-channel transport, and the PWA
shell. It deliberately stops where slice 1 (attention loop) begins — no
approvals inbox, no transcripts, no push triggers. Product decisions stay
authoritative in the argus docs
([OVERVIEW](../../exploration/argus/OVERVIEW.md),
[FLOW](../../exploration/argus/FLOW.md),
[DECISIONS](../../exploration/argus/DECISIONS.md)); this doc owns build
sequencing and the repo-mechanics decisions the exploration left open.

---

## Decisions this plan takes

Settled 2026-07-10 (operator + assistant session); recorded into
OVERVIEW/DECISIONS by P1's docs rider so the argus docs stay the source of
truth.

1. **Same repo, no restructure.** The SPA lives at top-level `ui/`; the Elixir
   app stays at the repo root. No apps/packages monorepo conversion, no
   umbrella, no separate client repo. Evidence for staying put: 834 lines
   across 71 docs files cite `lib/…` paths (the exploration corpus's file:line
   discipline), and the `.mcp.json` cwd contract, Dockerfile, install.sh,
   escript/release config, and check tasks all assume the current root. The
   couplings pull toward co-location: the schema→codegen loop wants atomic
   commits, the golden-SDL guard wants single-repo CI enforcement
   (*advertisement without mechanical enforcement rots* —
   [SYNTHESIS §5.5](../../exploration/argus/SYNTHESIS.md)), and the deploy
   story is per-node anyway.
2. **Each node serves the SPA.** The built client ships in `priv/static/argus/`
   and every gateway node serves it at `/argus` — same-origin with `/gql` and
   `/ws`, so no CORS surface exists at all. The service worker (P5) owns shell
   caching; skew tooling is needed regardless of who hosts. (OVERVIEW §2.6
   never named a host; this settles it.)
3. **pnpm, single package.** No workspaces, no turborepo until a second JS
   package actually exists (Tauri wrapper, extracted API client — both
   speculative). If one appears, workspaces arrive *inside* the `ui/` subtree;
   the Elixir app never moves.
4. **Codegen starts basic, deliberately.** `@graphql-codegen/cli` with the
   plain `typescript` + `typescript-operations` plugins — generated **types
   only**, no hook generation, no presets. Explicitly rejected:
   `typescript-react-apollo` and `client-preset` (Apollo recommends against
   both — operator-confirmed 2026-07-10, closing OVERVIEW §6.3's "pick when
   the time comes"). Iterate from working-and-boring as real usage teaches us.
5. **The SDL golden is committed and precommit-enforced.** `ui/schema.graphql`
   is regenerated by a mix task and byte-diffed by a check task in the
   `precommit` alias — resource drift without a regenerated client schema
   fails the gate, same pattern as `jidoclaw.system_prompt.check` /
   `jidoclaw.jido_md.check` / the MCP golden surface test.
6. **`mix precommit` stays node-free.** Only the Elixir-side SDL check joins
   the alias. The UI gate is `pnpm --dir ui typecheck && pnpm --dir ui test
   && pnpm --dir ui build`, documented in AGENTS.md and run when `ui/` is
   touched — precommit must stay runnable on nodes without a JS toolchain.
7. **Zero mutations in this program.** The bootstrap surface is read-only
   queries. The first mutation (`decideCase`, wrapping `Cases.decide/4`)
   arrives with slice 1, and config/trust mutations stay off GraphQL entirely
   (OVERVIEW §4.4, the CC2-4 lesson).

## Reuse / current state

- **Auth is already built for this.** `JidoClaw.Web.Plugs.ApiKeyAuth`
  validates Bearer / `x-api-key` and — the part that matters — calls
  `Ash.PlugHelpers.set_actor` (`web/plugs/api_key_auth.ex:27`). AshGraphql
  reads the actor from exactly that seam, so mounting Absinthe behind the
  existing `[:api, :api_auth]` pipelines (`web/router.ex`) yields
  policy-scoped queries with no new auth code.
- **No GraphQL deps exist yet** — `ash_graphql`/`absinthe` are absent from
  `mix.exs`. OVERVIEW §7 step 2 ("stand up AshGraphql") starts here.
- **Read-models to reuse, never rebuild**: `WorkflowView`,
  `RouteComposer.Observe`, AgentView (OVERVIEW §2.4 — resolvers reuse the
  modules the MCP tools read; no parallel query layer).
- **`Accounts.ApiKey` has a `:create` action + code interface but zero
  minting paths** — the known MY1-4a gap, already queued as
  [pre-argus-do-now #18](../pre-argus-do-now/README.md).
- **`assets/` is not this program.** The esbuild-bundled LiveView dashboard
  JS stays exactly as-is; `ui/` is a sibling, not a replacement.
- **The repo has zero `package.json` today** — P2 introduces the first node
  toolchain; `.gitignore` and CONTRIBUTING gain the corresponding entries.

## P1 — GraphQL read surface + SDL golden (keystone)

**Builds**: the `/gql` endpoint with a deliberately minimal read-only schema,
and the golden loop that keeps client and server honest.

- `mix.exs`: add `ash_graphql` (brings `absinthe`, `absinthe_plug`).
- `lib/jido_claw/projects/{projects,project}.ex`: AshGraphql extension;
  `projects` / `project(id)` queries. Safe field set: id, name,
  github_full_name, default_branch, timestamps.
- Orchestration domain + `workflow_run.ex`: `workflowRuns` / `workflowRun(id)`
  read-only. Safe fields: id, name/workflow_type, status, started_at,
  timestamps, project relationship. **Excluded by name**: the
  AshCloak-encrypted `resume_checkpoint` / `replay_inputs`, lease internals
  (`claim_token`, `claimed_by`, `claim_expires_at`). No steps, no events, no
  composer lineage yet — slice 1 adds them with their consumers.
- New `lib/jido_claw/web/graphql/schema.ex` (Absinthe schema over the two
  domains); router mounts at `/gql` behind `[:api, :api_auth]`; GraphiQL
  dev-env only.
- `lib/mix/tasks/jidoclaw.graphql.schema.ex`: dump SDL → `ui/schema.graphql`
  (committed golden — created by this phase ahead of the `ui/` scaffold).
- `lib/mix/tasks/jidoclaw.graphql_schema.check.ex`: regenerate, byte-diff,
  fail with regeneration instructions; joins the `precommit` alias beside the
  other `jidoclaw.*.check` tasks.
- Docs rider (same PR, per repo rules): record this plan's decisions into
  OVERVIEW §2.6/§4.4/§6.3 + DECISIONS; new `docs/system/graphql-surface.md`
  page + AGENTS.md Key Patterns bullet (joins `jidoclaw.system_docs.check`'s
  enforcement + the `docs/system/README.md` index).

**Tests**: 401 without a key; authed `projects` query returns rows; authed
`workflowRuns` respects actor scoping; an SDL-content test asserting the
schema contains **none** of the excluded field names (the
redaction-completeness pattern — enumerate the sensitive set, assert absence);
check-task red/green (mutated golden fails, regenerated golden passes).

**Done when**: `mix precommit` green including the new check; a curl with a
minted/seeded key returns projects over `/gql`; the golden is committed and
drift-guarded.

## P2 — `ui/` scaffold + codegen + first page

**Builds**: the client toolchain and the proof of the full loop
(schema → golden → codegen → typed query → rendered data).

- `ui/`: Vite + React + TS via pnpm. Deps: `@apollo/client`, `graphql`,
  `react-router`. Dev deps: `@graphql-codegen/cli`,
  `@graphql-codegen/typescript`, `@graphql-codegen/typescript-operations`,
  `vitest`.
- `ui/codegen.ts`: reads `ui/schema.graphql` + operation documents → generated
  types under `src/gql/` (gitignored; regenerated by `pnpm codegen`, which
  `typecheck`/`build` depend on).
- Apollo client: HTTP link to `/gql`, `x-api-key` header (dev:
  `VITE_API_KEY`); Vite dev proxy `/gql` → `localhost:4000`.
- First page: projects list rendering live data through generated types.
- Scripts: `pnpm codegen | typecheck | test | build`; vitest smoke test.
- `.gitignore`: `ui/node_modules/`, `ui/dist/`, `ui/src/gql/`.
- CONTRIBUTING: node/pnpm prerequisite + the UI gate commands.

**Tests**: vitest smoke (page renders from a mocked Apollo provider);
`pnpm typecheck` as the type-level gate — a stale golden breaks it, which is
the loop working.

**Done when**: with the server up and a key minted (pre-argus #18 or seed),
`pnpm dev` renders the projects list end-to-end; all four pnpm scripts green.

## P3 — Node-served SPA

**Builds**: decision 2 — the client as a per-node static artifact.

- Vite build outputs to `priv/static/argus/` (gitignored, like
  `priv/static/assets/`).
- Mix alias `ui.build` (cmd → `pnpm --dir ui build`); release/Docker docs note
  the ordering (`ui.build` before `mix release`).
- Endpoint `Plug.Static` gains the `argus` dir; catch-all `GET /argus/*`
  controller serves `index.html` for client-side routing, with an honest 404
  branch when no build exists (never a silent blank page).
- README/AGENTS.md build-commands update.

**Tests**: controller test covering both branches (fixture `index.html`
served; missing build → 404 with a build hint).

**Done when**: `mix ui.build && mix phx.server` serves the working SPA at
`/argus` with zero Vite involvement; deep links inside the SPA route
correctly on refresh.

## P4 — Channels substrate

**Builds**: the live half of OVERVIEW §2.4 — transport only, minimal payloads,
client refetch (§4.2 posture).

- `UserSocket` accepts the API key on connect params alongside its existing
  Ash session auth (OVERVIEW §4.4) — same-origin + tailnet makes params-borne
  keys acceptable for v1; the per-purpose short-lived ticket (t3code TC1-2 /
  FLOW §11) is the recorded upgrade path, not built here.
- First channel: `workflows:run:<id>` proxying `Orchestration.RunPubSub` run
  lifecycle (`orchestration:run:<id>` — already broadcast by
  `ReactorMiddleware`; today only LiveView consumes it). Payloads carry id +
  change type; the client refetches via GraphQL.
- `ui/`: `phoenix` (phoenix.js) dep; socket module with key auth; the runs
  page (added here) live-updates a run's status without refresh.
- Explicitly deferred to slice 1: `gates:user:<id>`, per-step delta
  projection from the `WorkflowEvent` log, `workflowEvents(afterSeq:)`
  catch-up, and the carry-events-vs-minimal decision on run topics (DECISIONS
  slice-1 open; the minimal posture here is compatible with either answer).

**Tests**: channel join rejected without a valid key; join + broadcast
delivers the minimal payload; socket auth covers both key and session paths.

**Done when**: two browser tabs on the SPA see a run's lifecycle transition
live; an unauthenticated socket connect is refused.

## P5 — PWA shell + skew guardrails

**Builds**: installability and the first skew defense — the two things a
service worker makes mandatory.

- `vite-plugin-pwa`: manifest, icons, service-worker shell caching
  (network-first for `/gql`; the SW never caches API responses in v1).
- Version advertisement: surface app version + SDL hash to the client (extend
  `GET /health` or a tiny `/gql` `systemInfo` field — decide in-phase); the
  SPA compares against its build-time pair and shows a block-with-refresh
  banner on mismatch (traycer TR2-4's recovery UX; full per-topic version
  manifests stay a slice-1+ concern).
- iOS/installed-PWA smoke: add-to-home-screen, standalone display, offline
  shell renders a "reconnect" state rather than a broken app.

**Tests**: unit tests for the skew comparator; vitest for the banner
component; manual installed-PWA checklist recorded in the PR.

**Done when**: the SPA installs to a phone home screen on the tailnet; a
deliberately version-skewed shell shows the refresh banner instead of
misbehaving silently.

## Deviations

*Record every deviation from this plan as it happens (per AGENTS.md
conventions): what the plan assumed, what the code revealed, what was chosen
and why, and whether it was a surfaced decision or a forced correction.*

### P1 (implemented 2026-07-11; P1 plan rev 4)

- **Check-task name aligned** *(surfaced decision, 2026-07-10)*: this README
  sketched an asymmetric pair (`jidoclaw.graphql.schema` /
  `jidoclaw.graphql_schema.check`); shipped as the symmetric
  `mix jidoclaw.graphql.schema` + `mix jidoclaw.graphql.schema.check`
  (matching the `jidoclaw.*.check` family).
- **`recentWorkflowRuns`, not `workflowRuns`** *(surfaced decision,
  2026-07-10/11)*: the list query is a NEW `:recent` read action
  (`inserted_at desc, id desc`, validated `limit` 1..200 default 50) named
  honestly for what it returns; slice 1's richer `workflowRuns` arrives
  additively later. Same shape for projects (`:alphabetical`).
- **`WorkflowRunStatus` required a real enum type** *(forced correction)*:
  the P1 plan's key fact said `:atom` + `one_of` auto-generates the GraphQL
  enum — false in ash_graphql 1.9.4, which hard-maps `Ash.Type.Atom` to
  `String` (and even an `Ash.Type.Enum` without `graphql_type/1` falls back
  to `:string`). The pinned SDL contract (a 7-value `WorkflowRunStatus`)
  was unambiguous, so `WorkflowRun.status` moved to a new
  `JidoClaw.Orchestration.WorkflowRun.Status` enum type
  (`graphql_type: :workflow_run_status`). Same text storage, same atom
  values everywhere; the one ripple: the Lua `jido.runs` status validator
  read the attribute's `one_of` constraint (enum types carry none) and now
  reads `Status.values/0`.
- **Timestamps needed explicit `public?: true`** *(forced correction,
  anticipated by rev 4)*: `create_timestamp`/`timestamps()` default
  private, and `show_fields` cannot publicize a private field — both
  resources declare their timestamps public, a deliberate shared Ash
  public-interface change.
- **Auth "bridge" became a tenant-activity GATE** *(surfaced decision,
  2026-07-11)*: `Project` is global (`actor_present()` is its whole
  policy), so a suspended tenant's valid key would read projects with a
  mere tenant-setter plug. `GraphqlTenantGate` 403s inactive tenants, 503s
  activity-check infra failures, fails closed on malformed actors — and its
  `ensure_active` read-first upsert is the one write behind the read-only
  surface (documented in `docs/system/graphql-surface.md`).
- **Disposition rides P1 via the shared Visibility seam** *(surfaced
  decision, 2026-07-11)*: this README's field sketch had no disposition;
  `disposition` + `findings_deferred_count` public calculations delegate to
  the now-public `Visibility.result_disposition/1` /
  `result_findings_deferred_count/1` (the camus C1-4 never-plain-green rule
  on GraphQL from day one) — the shared-derivation seam, not a
  WorkflowView-backed resolver.
- **GraphiQL is guarded, and compiled in test** *(forced correction from
  the rev-2 review)*: "GraphiQL dev-env only" was not enough — GraphiQL
  executes documents itself on non-HTML requests AND on HTML GETs carrying
  `?query=` (only document-less HTML requests render the interface).
  `GraphiqlGuard` passes only a bodyless, query-less HTML GET (body proven
  empty via bounded `read_body/2`, never Content-Length); the `/graphiql`
  scope compiles under `Mix.env() in [:dev, :test]` solely so route tests
  prove the guard.
- **Derived filter/sort disabled** *(surfaced decision, 2026-07-11)*:
  `derive_filter?(false)` + `derive_sort?(false)` on both resources — the
  bootstrap surface is fixed-shape; pagination/filters beyond `limit` stay
  out of scope. Complexity/token controls
  (`analyze_complexity: true, max_complexity: 200, token_limit: 5_000`)
  are pinned on the forward and route-test-proven.
- **Pre-existing reach smell cleared in `mcp/consumer.ex`** *(forced
  correction — gate unblock, not P1 scope)*: the full `mix precommit` run
  failed on one reach "Suboptimal patterns" finding at
  `lib/jido_claw/mcp/consumer.ex:592` (`Map.keys/1 → Enum.filter`), a file
  this change never touches (last modified four commits back; the finding
  reproduces standalone and most plausibly surfaced with 5884baea's
  `ex_ast` 0.12.0→0.12.9 bump under reach 2.7.5). Applied the
  tool-prescribed mechanical refactor (iterate the map directly via a
  `for` comprehension into `%{}`; zero behavior change;
  `test/jido_claw/mcp/` 89 passed). `docs/system/mcp-consumption.md` was
  deliberately NOT bumped — no documented contract moved.
- **JIDO.md checker extended; Frameworks line canonicalized** *(surfaced
  decision, rev 4)*: framework detection gained Bandit, Jido (`":jido"`
  substring — any jido_* dep implies the framework), and
  ash_graphql-implies-`Absinthe/GraphQL`; detection is a shared public
  `JidoClaw.JidoMd.framework_names/1` the check task derives its expected
  set from (new `:framework_names` check), and the committed line was
  rewritten to canonical detector output (gains Ecto + Absinthe/GraphQL,
  drops the underivable `1.7+`). Entry points gain `graphql/schema.ex`
  only when the file exists.

### P1 post-review corrections (2026-07-11)

- **Transport batching rejected — the aggregate-cost bypass** *(forced
  correction from the working-diff review)*: P1 treated the pinned
  complexity/token limits as the request-cost bound, but Absinthe.Plug
  natively parses transport batches (a JSON array body → `_json`, an
  `operations` query/multipart param, a binary `_json` query param) and
  threads the limits into each batch element's OWN pipeline — N
  individually cheap queries ride one request with unbounded aggregate
  cost, bounded only by the 8 MB body cap. No consumer batches (GraphiQL
  and the argus client post single objects), so `GraphqlBatchGuard` now
  heads the `:graphql` pipeline and 400s (`batching_not_supported`) on
  `_json`/`operations` key presence, value-type-blind — rejection chosen
  over an aggregate-cap knob for zero users.
- **Frameworks label normalized (Phoenix without LiveView)** *(forced
  correction from the working-diff review)*: the generator's interpolated
  label left a trailing space (`"Phoenix "`) whenever `phoenix` was a dep
  without `phoenix_live_view`, and the checker's trimmed comma-split parse
  could never match it — a freshly generated JIDO.md failed its own drift
  guard in any such project (this repo has LiveView, so the committed file
  was unaffected). The label is now built whole, and the round-trip test
  covers the Phoenix-without-LiveView scaffold.
